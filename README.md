# Magister Utils

Unofficial clients for [Magister](https://www.magister.nl). This project centers around a shared Magister package that handles all core Magister functionality, with implementations for a CLI, TUI, and MCP server. All components are in an early stage and are largely generated by AI agents.

## Layout

```
apps/mcli          JSON CLI (mcli)
apps/mtui          Interactive TUI (mtui)
apps/mcp           Next.js dashboard + remote MCP server
packages/shared    Magister client, auth, and presenters
packages/sdk       New standalone TypeScript SDK
```

`@magister/shared` talks to Magister's APIs and owns token storage. The apps are thin wrappers around it.

## TypeScript SDK

> [!WARNING]
> `magister-sdk` is a very early work in progress. Its API, types, authentication flow, and storage format may change without notice. It is not published for production use yet.

The new SDK is a cleaner, typed Magister client intended for direct use in TypeScript applications. It currently covers authentication, accounts, enrollments, schedules, grades, messages, assignments, and study guides, including message composition and file uploads.

See the [SDK README](packages/sdk/README.md) for setup, examples, the complete method reference, and current limitations.

## Requirements

Download the archive for your platform from the [latest release](https://github.com/nanderq/magister-utils/releases/latest), then extract it. The archive contains two standalone binaries:

- `mcli`: a JSON command-line client
- `mtui`: an interactive terminal client

On macOS and Linux, make the binaries executable and run the initial setup from the extracted directory:

```bash
chmod +x mcli mtui
./mcli setup
```

On Windows, run:

```powershell
.\mcli.exe setup
```

Setup walks through school URL, username, and password, then writes tokens to `~/.config/magister/tokens.json` (or `%USERPROFILE%\.config\magister\tokens.json` on Windows). That file is shared by `mcli` and `mtui`. Override the path with `MAGISTER_TOKENS_FILE` if you need to.

A leftover `tokens.json` in the working directory is still picked up as a fallback. Prefer the global file.

## CLI

`mcli` prints JSON to stdout. Useful for scripts and agents.

```bash
./mcli capabilities
./mcli account
./mcli schedule --from today --to today
./mcli grades
./mcli messages --limit 20
./mcli message 12345 --attachments
./mcli assignments
./mcli assignment 67890
./mcli study-guides
./mcli study-guide 111
```

Dates accept `today`, `tomorrow`, or `YYYY-MM-DD`. Errors also come back as JSON with a non-zero exit code.

## Terminal UI

```bash
./mtui
```

Interactive views for schedule, grades, messages, and assignments. Login lives in the TUI if tokens are missing. `q` or Ctrl+C exits.

## MCP server

The `apps/mcp` app is a Next.js demo dashboard with Google sign-in, then a Magister OAuth connect plus an authenticated remote MCP endpoint at `/api/mcp`. Clients send `Authorization: Bearer mag_mcp_...`. OAuth-only MCP clients are not supported. A more simplified MCP server is in the works and will replace this demo dashboard in the future.

See the MCP [apps/mcp/README.md](apps/mcp/README.md) for env vars, local setup, and Vercel deploy. Vercel is the recommended deployment target. The MCP server is self-hosted: operators are responsible for their deployment, stored data, retention policy, and access controls.

Tools: `get_account`, `get_schedule`, `get_grades`, `list_messages`, `get_message`, `list_assignments`, `get_assignment`, `list_study_guides`, `get_study_guide`.

## Development setup

Development requires [Bun](https://bun.sh) 1.3.14 or later. From the repository root:

```bash
bun install
bun run setup
```

Run the clients from source with `bun run mcli -- <command>` and `bun run mtui`. For example:

```bash
bun run mcli -- account
bun run mtui
```

Start the MCP app locally with `bun run dev:mcp`.

## Shared package

`@magister/shared` is the only place that talks to Magister.


| Export                        | What it is                              |
| ----------------------------- | --------------------------------------- |
| `@magister/shared`            | Client, auth helpers, presenters, setup |
| `@magister/shared/magister`   | `MagisterClient` and token helpers      |
| `@magister/shared/presenters` | Normalized API shapes                   |
| `@magister/shared/setup`      | Interactive `runSetup()`                |




## Scripts


| Command                 | What it does                                 |
| ----------------------- | -------------------------------------------- |
| `bun run setup`         | Interactive Magister login                   |
| `bun run mcli -- …`     | Run a CLI command from source                |
| `bun run mtui`          | Open the TUI from source                     |
| `bun run dev:mcp`       | Next.js MCP app on localhost:3000            |
| `bun run build:release` | Compile the CLI and TUI release binaries     |
| `bun run build`         | Compile the CLI, TUI, and configured MCP app |
| `bun run test`          | Run the shared and MCP unit tests            |
| `bun run typecheck`     | Type-check the monorepo                      |


Tagged releases are built for Linux, macOS, and Windows. They contain only the `mcli` and `mtui` binaries; deploy the MCP app through Vercel or any other host instead.

## Tokens

Treat `tokens.json` like a password. Rotating Magister credentials or wiping `~/.config/magister/tokens.json` means running `mcli setup` again (or `bun run setup` in a development checkout).
